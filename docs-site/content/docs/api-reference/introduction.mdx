The Cider API is a REST API over HTTPS. Everything you can do in the console, you can do with the API: create sandboxes and servers, pause and resume, take and restore snapshots, list nodes and their capacity, and read metrics.

## Base URL

```text
https://api.cider.build
```

All paths on this reference are relative to that base. There is no version prefix.

## Authentication

Every request carries an API key in the `Authorization` header:

```http
Authorization: Bearer cider_live_2f9c…
```

Create keys in the console under **Settings → API keys**. See [Authentication](/api-reference/authentication).

## Your first request

```bash
curl https://api.cider.build/nodes \
  -H "Authorization: Bearer $CIDER_TOKEN"
```

## Conventions

- **JSON everywhere.** Request bodies are `application/json` unless the endpoint says otherwise. `POST /sandboxes` takes `multipart/form-data` so you can upload a project archive.
- **IDs** are 32 lowercase hexadecimal characters. Sandbox IDs carry a `cider-` prefix. Sandbox IDs are also the VM name on the node.
- **Timestamps** are ISO 8601 in UTC, for example `2026-08-19T14:02:11.000Z`.
- **Bytes** are integers. Memory and disk fields end in `_bytes`. 1 GiB = `1073741824`.
- **Empty responses** are `204 No Content`.
- **Endpoints without a body** (`pause`, `stop`, `start`, `retry`, `POST /sandboxes/{id}/snapshots`) take no request body. `POST /sandboxes/{id}/resume` and `POST /snapshots/{id}/restore` take a JSON object; send `{}` if you have nothing to pass.
- **Long operations** return at once. `POST /servers` returns `provisioning`; poll `GET /servers/{id}` until `running` or `failed`.

## Organization scope

An API key belongs to one organization. Every resource you read or write is in that organization. There is no cross-organization access.

## Rate limits and capacity

The API itself is not rate limited for normal use. Capacity limits come from your nodes: each holds at most two VMs. When nothing fits you get `422` or `429` with a clear `detail`. See [Errors](/api-reference/errors).

## OpenAPI

The full specification is available as [`openapi.yaml`](/api-reference/openapi.yaml). Import it into your HTTP client or generate an SDK from it.
